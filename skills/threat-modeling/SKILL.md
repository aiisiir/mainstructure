# Threat Modeling Skill

1. List assets, actors, trust boundaries, entry points, and sensitive flows.
2. Consider spoofing, tampering, repudiation, information disclosure, denial of service, and privilege escalation as prompts—not as a substitute for domain-specific analysis.
3. Test authorization on server-side operations and tenant/object boundaries.
4. Identify secrets, logging, validation, rate limiting, replay/idempotency, abuse, dependency, and recovery concerns.
5. Rank threats by impact and likelihood; assign mitigations, owners, and verification tests.
6. Mark unresolved critical threats as release blockers.

Never state that a system is secure merely because a threat model document exists.
