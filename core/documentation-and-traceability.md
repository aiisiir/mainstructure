# Documentation and Traceability

Documentation exists to transfer decisions and enable safe change, not to maximize paperwork. Keep each artifact close to the work it governs, name an owner where decisions can go stale, and update docs when behavior changes.

Minimum project documentation: brief, requirements, project profile, relevant diagrams, ADRs, threat model, test strategy, operational/runbook notes, release checklist, and applicable SEO plan.

Use explicit status labels such as `proposed`, `accepted`, `rejected`, `superseded`, and `needs-validation`. Distinguish known facts from assumptions. Link evidence rather than copying large outputs into prose.

Trace requirements to acceptance criteria and verification. A traceability gap is visible work, not a reason to invent a test. Keep docs concise and remove stale duplicates.
