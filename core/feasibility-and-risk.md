# Feasibility and Risk Review

Assess these dimensions before stack commitment:

- **Product:** evidence of user need, adoption risks, success measures.
- **Technical:** feasibility, integration uncertainty, workload, data model, latency, scale, reliability.
- **Delivery:** skills, staffing, deadline realism, dependencies, testing capacity.
- **Operational:** hosting, deployment, support, monitoring, backups, restore, incident ownership.
- **Security/privacy:** data sensitivity, threat actors, access boundaries, retention, regulatory/contract requirements.
- **Discoverability:** SEO value, rendering/crawlability, content scale, localization, migration/redirect risk.
- **Economics:** build cost, run cost, licensing, vendor lock-in, migration and exit cost.

Each material risk must include likelihood, impact, detectability where useful, mitigation, owner, and trigger. Use a simple qualitative scale if numeric precision would be misleading.

A feasibility review should recommend one of: proceed, proceed with conditions, run a time-boxed spike, reduce scope, choose an alternative, or stop. A spike must specify the question, timebox, method, evidence required, and decision it will influence.
