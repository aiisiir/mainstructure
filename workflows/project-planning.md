# Workflow: Project Planning

1. Confirm the approved brief, prioritized requirements, project profile, and hard constraints.
2. Resolve stack selection and material architecture decisions; list unresolved decisions separately.
3. Build requirement-to-acceptance-test traceability for high-priority requirements.
4. Divide work into end-to-end vertical slices that produce observable value.
5. Schedule risky integrations, migrations, auth/authorization, search/rendering decisions, and operational deployment early enough to learn.
6. Add test automation, security checks, accessibility, SEO checks, performance budgets, documentation, and content work to the plan.
7. Estimate uncertainty honestly; use ranges and confidence rather than false precision.
8. Define release criteria, rollback conditions, and who can approve residual risk.

**Exit condition:** the plan has dependency order, acceptance evidence, owners, and explicit assumptions.
