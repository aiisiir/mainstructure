# Contributing to the Framework

1. State the recurring problem and evidence from one or more products.
2. Decide whether the fix belongs in core, a project profile, an adapter, a template, or a single product.
3. Make the smallest useful change; do not abstract a one-off need into core prematurely.
4. Update affected cross-links, templates, and quality checks.
5. Inspect the GitHub Actions result and review any unvalidated assumptions. No Python installation or local custom CLI is required.
6. Update `CHANGELOG.md` with impact and required actions for existing products when contracts change.
7. Explain trade-offs and checks not run.

Contributions should improve clarity, evidence, usability, or measurable quality—not merely add process.
